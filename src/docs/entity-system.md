# Entity System Documentation

## Overview

The entity system provides a structured way to define, register, and visualise game entities. Each entity is a self-contained module with its own state, animation, rendering, and configuration.

## Architecture

```
src/entities/
    <entity-name>/
        <EntityName>.js          — Main entity class (update/render/start/stop/reset)
        <EntityName>Config.js    — Centralized configuration
        <EntityName>State.js     — Mutable state (data layer)
        <EntityName>Animator.js  — Procedural animation
        <EntityName>Renderer.js  — Canvas rendering (reusable, accepts any canvas)
        entity.js                — Entity descriptor (discovered by build script)

src/entities/entity-manifest.js   — Generated manifest of all entity descriptors
src/entities/entityregistry.js    — Central registry consuming the manifest
scripts/discover-entities.mjs     — Build-time discovery script
```

## Entity Structure

Each entity directory contains:

- **Main class** (`<EntityName>.js`): Implements `update(deltaTime)`, `render()`, `start()`, `stop()`, `reset()`. Uses its own state, animator, and renderer instances.
- **Config** (`<EntityName>Config.js`): Centralized configuration including sprite paths, dimensions, offsets, animation parameters, canvas dimensions, and background color.
- **State** (`<EntityName>State.js`): Data layer only. Stores offsets, scales, animation time, paused state, active state, dimensions, and animation offsets. Provides `setComponentProp`/`getComponentProp` for editor use.
- **Animator** (`<EntityName>Animator.js`): Procedural animation (idle bob + sway). Stores animation offsets on `state._animOffsets` so the renderer can apply them independently of component offsets.
- **Renderer** (`<EntityName>Renderer.js`): Canvas 2D rendering. Draws sprite layers independently (face, hands, etc.). Designed to be reusable — accepts any canvas/context. Can be embedded or overlaid onto game rendering.
- **Descriptor** (`entity.js`): Exports `DESCRIPTOR` with entity metadata: id, label, classPath, configPath, spriteComponents, defaultConfig, and class references.

## Entity Registration

Entities are registered via `src/entities/entity-manifest.js`, which is generated by `scripts/discover-entities.mjs` at build time. The script scans `src/entities/*/entity.js` and creates import statements for each descriptor.

To add a new entity:
1. Create a new directory under `src/entities/`
2. Add an `entity.js` exporting `DESCRIPTOR`
3. Run `scripts/discover-entities.mjs` to regenerate the manifest (or manually add the import to `entity-manifest.js`)

## Debug Preview

The debug menu provides an **Entity Editor** (button in control panel) that:
- Enumerates all registered entities from the EntityRegistry
- Instantiates the selected entity's real implementation (not a mock)
- Provides a canvas preview with controls generated from the entity descriptor
- Allows experimentation with sprite positioning, scaling, animation timing, and state

The debug preview is a **consumer** of the entity implementation — it does not contain a second implementation. Removing the debug preview does not affect the entity itself.

## Renderer Integration

The entity renderer is designed for future game overlay/integration:

```javascript
// In game rendering:
const renderer = new JimHateRenderer(gameCanvas, JIM_HATE_CONFIG);
const entity = new JimHate(gameCanvas, JIM_HATE_CONFIG);
// In game loop:
entity.update(deltaTime);
entity.render();
```

The renderer draws to any canvas — it doesn't care whether it's a debug overlay or game world.

## Sprite Organisation

Sprites are stored in `src/img/sprites/` following the existing convention:
```
src/img/sprites/<entity-category>/<entity-name>/<sprite-name>.png
```

Each entity's config references its sprites via relative paths from the HTML root.

## State/Animation Convention

Animation offsets are stored on `state._animOffsets` (x, y) and applied to the entity centre in the renderer. This separates component-level offsets (face X/Y, hands X/Y) from entity-level animation (bob, sway).

```
Entity centre = canvas centre + _animOffsets.x + _animOffsets.y
Sprite position = entity centre + component.offsetX - sprite.width/2
```

## Future Expansion Points

Each entity is designed to be extended with:
- Custom movement / pathfinding
- AI / state logic (behaviour trees, decision making)
- Attack animations / combat systems
- Collision detection integration
- Visual effects (particles, shaders)
- Multiple sprite layers
- Custom interaction logic
- Boss/god-like behaviour

These are not implemented yet — the initial version focuses on sprite rendering and basic idle animation.
